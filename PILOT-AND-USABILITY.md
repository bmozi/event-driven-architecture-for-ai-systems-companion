## Observable gates

1. recognizes the need for trustworthy awareness;
2. distinguishes message, event, and reaction;
3. completes the gateway without invented authority;
4. supports an outside-team read-back;
5. finds or discusses seeded semantic and loop failures;
6. produces evidence and a next decision with an assigned owner or explicit
   `UNASSIGNED` state plus assignment authority/trigger, and a justified date or
   evidence-based review trigger; and
7. keeps message activity separate from business value.

State progression is `PREPARED -> PILOTED -> REVISED FROM OBSERVATION ->
REPEATED`. Name participant and version scope before using
`PRACTITIONER-TESTED`.
